# apps/api

Guidance for `@travel-pocket/api`, the backend API. Repo-wide rules — including the mandatory Isolation Rules — live in the root [CLAUDE.md](../../CLAUDE.md). Paths in this file are relative to `apps/api/`.

Hono app running on Cloudflare Workers, storing trip data in D1. Locally, `wrangler dev` simulates D1 in `.wrangler/state/`; no Cloudflare account and no frontend are needed.

## Commands

Run from the repo root (or drop the `-F @travel-pocket/api` prefix when inside `apps/api/`):

```bash
pnpm -F @travel-pocket/api db:migrate:local   # Apply migrations/ to the local D1 (run once, and after adding a migration)
pnpm -F @travel-pocket/api dev                # wrangler dev on :8787 (same as root `pnpm dev:api`)
pnpm -F @travel-pocket/api db:seed --token dev-token   # Load @travel-pocket/data into the running API
pnpm -F @travel-pocket/api build              # Type check only (tsc -b)
pnpm -F @travel-pocket/api lint               # ESLint
pnpm -F @travel-pocket/api test               # Vitest inside workerd (@cloudflare/vitest-plugin)
pnpm -F @travel-pocket/api cf-typegen         # Regenerate worker-configuration.d.ts
pnpm -F @travel-pocket/api db:migrate:remote  # Apply migrations to the remote D1
pnpm -F @travel-pocket/api run deploy         # wrangler deploy (`run` is required: `pnpm deploy` is a pnpm built-in)
```

First-time setup: copy `.dev.vars.example` to `.dev.vars` (git-ignored) so local PUTs accept `dev-token`.

`db:seed` takes `--url` (default `API_URL`, then `http://localhost:8787/api`) and `--token` (default `ADMIN_TOKEN`), so the same script seeds local and remote.

## API

All routes live under `/api` (`basePath`). Data shapes and the `ID_PATTERN` / `DATA_TYPES` validation constants come from `@travel-pocket/shared`.

| Route | Behavior |
|---|---|
| `GET /health` | `{ ok: true }` |
| `GET /trips` | `Trip[]` ordered by `position` |
| `PUT /trips` | Upsert only — never deletes rows. Array index becomes `position` |
| `GET /trips/:tripId/:type` | `TripDataMap[type]`; 404 if the trip does not exist |
| `PUT /trips/:tripId/:type` | Replaces the trip's data of that type in one `DB.batch()` (one transaction); 404 if the trip does not exist |

- Every `PUT` requires `Authorization: Bearer <ADMIN_TOKEN>` (`hono/bearer-auth`); the token is checked before anything else.
- 400 for an invalid `tripId`, unknown `type`, non-array or non-JSON body, or data that violates a table constraint (missing field, duplicate id).
- CORS allows only the comma-separated origins in the `CORS_ORIGINS` var.

## Data Layer

- `migrations/0001_init.sql` — `trips`, `itinerary_days`, `itinerary_items`, `shops`, `info_items`. Every child table cascades from its parent, and D1 enforces foreign keys by default, so **`PUT /trips` must stay an upsert**: deleting or replacing a trip row wipes its itinerary, shops and info.
- `src/db/<type>.ts` — row types, row → shared type converters (`toTrip`, `toShop`, …), and the query / replace functions. `src/db/index.ts` dispatches by `DataType`.
- Array and nested values (`tags`, `links`, `description`) are stored as JSON text. `day` is stored as text, so numeric days come back as strings. `category` has no CHECK constraint because real data uses values outside the union type.
- Writes pass the whole array as one JSON parameter and insert it with `INSERT … SELECT … FROM json_each(?)`. This keeps each request at a fixed, small number of statements regardless of data size (the Free plan allows 50 queries per invocation and 100 bound parameters per query). Keep new write paths in this form rather than one `INSERT` per row.

## Configuration

- `wrangler.jsonc` — D1 binding `DB` (`database_name: travel-pocket`), `CORS_ORIGINS` var, `ADMIN_TOKEN` declared in `secrets.required`. Production sets `ADMIN_TOKEN` with `wrangler secret put`.
- `worker-configuration.d.ts` is generated by `cf-typegen` and committed. Rerun it after changing `wrangler.jsonc` or upgrading wrangler.
- TypeScript is split like `apps/web`: `tsconfig.worker.json` (`src/`, Workers types), `tsconfig.node.json` (`scripts/`, `vitest.config.ts`), and `test/tsconfig.json`; `tsconfig.json` only references them.

## Testing

- Tests run inside workerd via `@cloudflare/vitest-plugin` (formerly `@cloudflare/vitest-pool-workers`), against a local D1.
- `vitest.config.ts` reads `migrations/` into a `TEST_MIGRATIONS` binding; `test/apply-migrations.ts` applies them before tests. It also binds `ADMIN_TOKEN=test-token`, so tests never depend on `.dev.vars`.
- Storage is isolated per test file, not per test: `beforeEach` in `test/api.test.ts` clears `trips` (which cascades).
- Tests call the Worker through `exports.default.fetch` from `cloudflare:workers`.
